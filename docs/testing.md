# 實機測試說明（Task 01 驗收）

**規格書要求：不得只用桌面瀏覽器結果驗收。** 本頁是你（或店員）拿手機測試時照著做的清單。

## 準備

1. 依 README 把網頁發布到 GitHub Pages，取得 `https://….github.io/…/` 網址。
2. 在電腦螢幕全螢幕顯示 `assets/targets/test-target-001.png`（螢幕亮度中高），或用彩色列印 A5 以上並貼平。
3. 手機開啟「網址 + `?debug=1`」，例如 `https://….github.io/…/?debug=1`。

## 測試項目（iPhone Safari、Android Chrome 各做一遍）

| # | 步驟 | 通過標準 |
|---|---|---|
| 1 | 按「開始 AR 體驗」，在彈出視窗按允許 | 進入相機畫面，下方出現「請將相機對準測試圖案」 |
| 2 | 對準圖案約 30 公分 | 3 秒內出現小人偶，提示變綠色 |
| 3 | 點小人偶 | 揮手；再點一次跳躍；動畫結束回到待機 |
| 4 | 把相機移開圖案 | 小人偶消失；再對準會重新出現 |
| 5 | 改變距離（20／40／60 公分）與角度（正面、斜 45°） | 記錄哪些條件仍可辨識 |
| 6 | 改變光線（明亮、昏暗、反光） | 記錄結果 |
| 7 | 按「結束」，再按「開始」，重複 10 次 | 每次都正常；手機不明顯發燙、不閃退 |
| 8 | 開始時按「拒絕」相機權限 | 顯示「需要相機權限」與開啟方式 |
| 9 | 用 LINE 內建瀏覽器開啟網址 | 顯示 App 內瀏覽器提醒；記錄相機是否可用 |
| 10 | 開飛航模式後載入 | 顯示「活動資料載入失敗」 |

## 記錄表（複製一份填寫）

| 機型 | 系統版本 | 瀏覽器 | #1 | #2（首次辨識 ms） | #3 | #4 | #5 | #6 | #7 | #8 | #9 | #10 | FPS | 備註 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | | | | | | |

`?debug=1` 畫面左上角會顯示 FPS、首次辨識時間（從按下「開始」起算）、找到／遺失次數。

## 鎖定 MindAR 的門槛（建議）

- iPhone 與 Android 各至少一支實機，#1～#4、#7、#8 全部通過。
- 正常光線、30～50 公分、正面角度：辨識成功率感覺穩定，首次辨識 < 3 秒。
- 畫面 FPS 肉眼流暢（建議 ≥ 20）；重複開關 10 次無閃退。
- 若有任一平台無法達標 → 先停下來回報，再評估備案（8th Wall 開源版／AR.js），**不要**硬改程式繞過。
